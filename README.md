# BLOCKFIRE

PSX 레트로 그래픽의 웹 전술 FPS (Three.js + TypeScript + Vite).

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run server     # 온라인 서버 (ws://localhost:5174) — 메뉴의 PLAY로 접속
npm run build      # 타입 검사 + 프로덕션 빌드 (dist/)
npm run typecheck  # 클라이언트 + 서버 타입 검사
```

온라인: 서버를 띄운 뒤 메뉴 **PLAY** → 이름 입력 → **방 만들기**(4글자 코드가 나옴) 또는 코드로 **참가** → 팀(A/B, 최대 5명)·캐릭터 선택 → 방장이 **경기 시작**.
다른 컴퓨터에서 접속할 때는 같은 주소의 5174 포트로 붙습니다. 다른 서버 주소는 `?server=ws://주소:포트`로 지정합니다.
`FAST=1 npm run server`는 짧은 테스트 경기(구매 10초, 2라운드마다 교체, 3승)와 개발용 순간이동을 켭니다.

## 배포

게임 파일과 온라인 서버가 **Node 서버 하나(포트 하나)** 로 함께 동작합니다.

```bash
npm install
npm run build:all   # 게임(dist/) + 서버(dist-server/) 빌드
npm start           # http://주소:PORT (기본 5174) — 게임과 WebSocket이 같은 주소
```

- 호스팅: WebSocket 연결을 계속 열어 둘 수 있는 Node 호스팅 (Render Web Service, Railway, Fly.io, VPS 등). Build Command `npm install && npm run build:all`, Start Command `npm start`. 포트는 환경 변수 `PORT`를 따릅니다. 상태 확인 주소: `/health`
- Vercel·Netlify·GitHub Pages 같은 정적 호스팅은 게임 파일만 올릴 수 있고 온라인 서버는 돌릴 수 없습니다. 나눠 올릴 때는 빌드 전에 `VITE_SERVER_URL=wss://서버주소`를 지정합니다.
- HTTPS 페이지에서는 자동으로 `wss://`로 접속합니다.

### 무료 배포: Firebase Hosting(web.app) + Render 무료 서버

게임 화면은 **Firebase Hosting**(무료 Spark 요금제, `https://<프로젝트ID>.web.app`), 온라인 서버는 **Render 무료 Web Service**에 올립니다. 둘 다 결제 수단 없이 무료입니다. Firebase 무료 요금제는 게임 서버(WebSocket)를 돌릴 수 없어서 서버만 따로 둡니다.

1. 코드를 GitHub 저장소에 올립니다.
2. 온라인 서버 → Render: render.com 가입 → **New → Blueprint** → 저장소 선택. 저장소의 `render.yaml`대로 무료·싱가포르 서버가 만들어집니다. 끝나면 `https://blockfire-server-xxxx.onrender.com` 주소가 나옵니다 (`/health`에서 `ok`가 보이면 정상).
3. 게임 화면 → Firebase Hosting:
   ```bash
   firebase login
   firebase use --add            # Firebase 콘솔에서 만든 프로젝트 선택 (무료 Spark 그대로)
   ```
   Windows PowerShell (위 Render 주소를 `wss://`로):
   ```powershell
   $env:VITE_SERVER_URL="wss://blockfire-server-xxxx.onrender.com"; npm run deploy:hosting
   ```
4. `https://<프로젝트ID>.web.app` 접속 → PLAY.

무료 서버의 한계: 15분 동안 아무도 접속하지 않으면 서버가 잠들고, 다음 첫 접속 때 깨어나는 데 1분쯤 걸립니다 (그동안 대기실에 "서버를 깨우는 중…"이 표시되고 자동으로 다시 접속). 서버가 다시 시작되면 열려 있던 방은 사라집니다. 경기 방식에서 **SHORT**(5승)를 고르면 경기가 짧게 끝납니다.

조작: 좌클릭/우클릭 두 가지로 쓰는 능력은 키를 누르면 꺼내 들고 클릭으로 사용(같은 키·무기 교체로 집어넣기). 충격파는 누르고 있다가 떼면 발동. 설치형(가시덤불·섬광 꽃·드론)은 다시 누르면 발동.

전술 지도(src/ui/TacticalMap.ts): 좌클릭 지점 추가 · 우클릭 취소 · 같은 능력 키/Enter 발사 · Esc 닫기(충전 유지). 봇은 지도 대신 목표 지점을 쓴다.

능력 작동 방식은 전술 FPS의 대표 역할군 구성을 참고했고, 이름·설정·외형은 자체 제작이다. 상태 이상: 충격·억제·무력화·감속·가속·자극·쇠약·추가 체력 (src/abilities/StatusEffects.ts).

### 효과음 확인

개발 서버에서 `/audio-lab.html`을 열면 모든 합성 효과음을 들어 보고 파형·스펙트럼·클리핑·변형 유사도 검사 결과를 볼 수 있습니다. 녹음 샘플을 불러오지 못하면 같은 역할의 합성음으로 자동 대체됩니다.

### 새 무기 추가

`src/weapons/weaponData.ts`에 항목을 추가합니다. `hold`는 손 위치(바운딩 박스 기준 비율)로, 모델마다 손잡이 위치가 달라서 직접 지정합니다.

### 캐릭터 애니메이션

캐릭터는 Mixamo Y Bot이고, 3인칭 동작은 Mixamo 애니메이션(`src/player/AnimationLibrary.ts`)으로 재생합니다.

- 하체: 이동 방향/속도에 따라 대기·걷기·달리기·뒤로·좌우 이동 클립을 섞고 위상을 동기화합니다. 클립의 원래 이동 속도를 기록해 실제 이동 속도에 맞춰 재생합니다.
- 상체: 조준 대기 / 사격 / 재장전 클립
- 절차적 보정: 조준 각도에 따른 허리 굽힘, 왼손 IK(핸드가드), 무기 꺼내기
- 애니메이션이 아직 없는 동작(앉기, 사망)은 절차적으로 만듭니다. Mixamo 클립을 추가하면 `AnimationLibrary.ts`의 `FILES`에 등록해 교체할 수 있습니다.
- 1인칭 팔은 애니메이션 대신 IK로 무기를 잡습니다.

### 맵

| 맵 | 설명 |
|---|---|
| FOUNDRY | 노을 진 주조 공장 · 중앙 실내 건물 · A 고지대 |
| DRYDOCK | 해 질 녘 조선소 · 지붕 덮인 중앙 통로 · 양쪽 실내 창고 |
| MERIDIAN | 사막 관측소 · 양 끝 설치 구역 · 기둥이 선 중앙 광장 |

격자 한 칸은 3.75m입니다 (MapDefinition.cellSize).

연습·봇 대전은 캐릭터 선택 화면의 MAP 줄에서, 온라인은 대기실에서 방장이 고릅니다(무작위 / 맵 지정). 무작위는 지난 맵과 다른 맵을 고릅니다.

### 새 맵 추가

`src/maps/drydock.ts`를 참고해 `MapDefinition`을 작성하고 `src/maps/index.ts`의 `MAPS`에 넣습니다. 범례는 `src/maps/MapData.ts`에 있습니다. 그다음 반드시 검사합니다:

```
npm run check:maps
```

눈에 보이는 박스끼리 부피가 겹치거나, 같은 방향을 보는 면이 같은 평면에서 겹치거나(Z-파이팅 깜빡임), 공격 스폰에서 A·B 구역·수비 스폰까지 걸어갈 수 없거나, 들어갈 수 없는 빈 칸이 있으면 실패합니다.
